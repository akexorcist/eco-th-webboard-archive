ว่าทำไมรักษา Pet ที่ยังไม่ได้เปลี่ยนชื่อถึงทำให้เกิด Buffer Overrun Detected??

ข้างล่างนี้เป็นการเดาล้วนๆ =>

1. อะไรคือ Buffer Overrun??
ตอบ: ความยาวค่าตัวแปรที่ตั้งไว้มีขนาดน้อยกว่าค่าที่ถูกใช้จริงๆ ยกตัวอย่าง:

สมมุติว่าเราสร้างตัวแปลไว้เก็บชื่อ Pet ขนาด 10 ตัวอักษร (char petName[10])

แต่ว่าชื่อ Pet เราดันมีขนาดเกิน 10 ตัวอักษร (myPetName = "Nekomata (Sumire)")

ถ้าเราพยายามเอา myPetName (17 ตัวอักษร) ไปใสใน petName (รับได้ 10 ตัวอักษร) ก็จะทำให้เกิด Buffer Overrun ได้ คือพยายามใช้เกิดความจุ

2. แล้วเกี่ยวอะไรกับการรักษาไม่ได้ละ??
ตอบ:เดาว่าโปรแกรมเมอร์คงกำหนดความยาวชื่อใน function การรักษา Pet ไว้น้อยกว่าที่ควรจะเป็น

เหมือนที่เราไม่สามารถตั้งชื่อตัวละครยาวๆได้นั่นแหละครับ สมมุติเขากำหนดให้ตั้งได้แค่ 10 ตัวอักษร เราก็มีชื่อได้ไม่เกิด 10 ตัวอักษร

แต่คงลืมนึกถึงชื่อ Pet ที่ระบบมันตั้งชื่อมาแล้ว (ว่ามันเกิน 10 ตัวอักษรไปแล้ว) เลยทำให้เกิด Buffer Overrun ขึ้น

สมมุติว่าเราแฮกระบบเข้าไปตั้งชื่อตัวละครเราสัก 50 ตัวอักษร ผมว่าตัวละครเราก็คงทำให้เกิด Buffer Overrun เหมือนกัน ไม่ว่าจะทำอะไร

3. แล้วจะแก้ปัญหาได้อย่างไรละ??
ตอบ: 1. โปรแกรมเมอร์ก็ต้องเขียน code ใหม่เพื่อกำหนดตัวแปลชื่อ Pet ให้รับได้ยาวขึ้น

2. ใช้ /GS ไม่ก็ <strsafe.h> library เพื่อช่วยสร้าง buffer เผื่อมันเกินขึ้นมา
